# 2026-08-29 跨端问题修复复盘

## 目的

本文件记录本轮问题的共同根因、正确修复边界和防复发规则。

后续修改必须先阅读本文件及 `REGRESSION-CHECKLIST.md`，不能只验证当前页面。

## 本轮结论

问题并非来自单一页面，而是集中在四类边界：设备能力、数据来源、厂商协议时序、调试/发布运行方式。

修复原则是以设备和服务端真实返回为准，不猜能力、不伪造数据、不把一种来源的数据当成另一种来源。

## 问题、根因与防复发约束

| 问题 | 根因 | 本轮处理 | 防复发约束 |
| --- | --- | --- | --- |
| iOS 设备地址显示为乱码或 UUID | CoreBluetooth UUID 被误当成 MAC 展示 | 连接仍使用 UUID；只有 SDK 返回且通过格式校验的地址才显示为 MAC | UUID 永远标为“iOS 连接标识”，不得截取或改写成伪 MAC |

| 换号后看到上一账号数据，或旧请求写入新账号 | 健康库、游标和异步任务曾按安装维度共享，没有稳定账号所有者及登录代次 | 健康、运动、预警、元数据、游标和消息按稳定账号隔离；同步与回调绑定登录代次 | 所有持久化读写必须显式带 owner；换号时先切代次，旧代次结果一律丢弃 |
| v5 升级后旧健康数据消失或被新账号继承 | 旧库没有账号列；直接归给当前任意登录账号会造成越权，永久留在未归属区又会让原用户看不到 | 旧数据先迁入 `legacy-unscoped`，仅启动时已持久化账号可在单一事务中认领；secure vault 保存一次性 migration marker | 认领尝试只能发生一次且必须原子覆盖全部健康、运动、预警、元数据、游标和消息表；首次迁移未登录也写 marker，后续账号不得继承 |
| 401 刷新后串号或旧 Token 复活 | 多请求并发刷新，且刷新结果没有校验发起时账号和登录代次 | 同账号刷新单飞；提交刷新结果和重放请求前执行登录代次 CAS | Token 刷新必须同时绑定账号、旧 Token 和登录代次，任何一项变化都拒绝提交 |

## 本轮发现的交叉回归风险

1. 清洗心电数据的执行顺序会影响来源判断。实时 App 测量必须先标记为 `app_measurement`，再执行质量校验。

2. 云同步完成后可能遇到页面已销毁。异步回调必须先检查控制器是否已释放，再通知 UI。

3. “为了让入口可见”而补默认能力，会造成入口可点但设备永远无响应。能力必须来自“设备支持 + 桥接实现”。

4. 同一指标可能来自自己的手表历史、App 手动测量和远程成员。展示、预警、上传和去重都必须保留来源。

5. 数据库结构迁移成功不等于用户可见性正确。迁移测试必须同时验证原账号可认领、第二账号不可继承、认领中断不会留下半迁移状态。

6. 推送 SDK 可能把同一事件分别作为通知回调和数据回调交付。去重需要稳定事件 ID 与投递标记，不能只按时间或文案判断。

7. 时区测试夹具也可能制造假失败。跨日样本必须显式表达中国时区日界线，不能使用随宿主 UTC/本地时区变化的隐式 `DateTime`。

## 固定数据契约

- `watch_history`：手表历史同步，只允许以设备原始时间入库。
- `app_measurement`：用户在 App 内发起的测量，可触发当前会话的交互反馈。
- `remote_member`：远程关爱成员数据，只用于成员详情，不混入自己的趋势与预警。
- `manual_entry/imported/unknown`：必须保持原来源，不得自动升级为设备真实测量。

心电 `rawVersion=2` 只表示已换算、可解释的真实 mV 波形；它不是诊断结论。

## 后续修改的停线条件

以下任一情况发生时，不得提交为“完成”：

- 远端基线未确认，或本地存在来源不明的覆盖修改。
- 某个入口依赖的设备能力或原生桥接没有同时确认。
- 只跑定向测试，没有跑全量测试和双端构建。
- 只验证 Debug 附加启动，没有验证 iOS Profile/发布形态独立启动。
- 真机没有产生有效样本，却用模拟值或旧截图代替结论。

## 追加复盘：通知、表盘、电量与在线升级

以下内容是本轮新增结论，只补充既有复盘，不覆盖上文历史。

| 问题 | 根因 | 防复发约束 |
| --- | --- | --- |
| 健康页红点固定常亮，或刷新后新通知消失 | 页面曾使用固定红点；远端未读缓存又可能直接覆盖刚写入的本地事件 | 红点必须由统一消息收件箱派生，未读为 0 时隐藏；本地新事件与远端未读按稳定事件 ID 合并，陈旧远端计数不得压掉尚未同步的新本地未读，禁止用单个远端整数直接覆盖本地状态 |
| 同一推送弹两次或重复入箱 | JPush 可能分别触发系统通知回调和数据回调，原载荷还可能嵌套在 `extras` | 先归一化载荷，再按稳定事件 ID 和投递标记去重；数据通知只在系统未展示时生成本地提醒，重复事件不新增收件箱记录 |
| 推送泄露健康信息或跳转到任意页面 | 把业务数据和目标路由直接当作可信推送载荷 | 推送只允许 `schema_version`、`event_id`、`event_type`、`entity_id` 和白名单路由；不得携带手机号、Token、健康数值或诊断信息；锁屏只显示通用提醒，客户端收到后重新读取服务端实体，非白名单路由直接拒绝 |
| 推送凭据被写入仓库，或生产包在凭据缺失时静默降级 | 调试占位配置与生产配置边界不清 | JPush、APNs 和 Android 厂商通道凭据只能从受保护的 GitHub Environment 注入；生产构建缺少任一必需凭据时必须硬失败，不能使用默认值、占位值或关闭推送后继续发布；日志、产物和源码都不得回显凭据 |
| Android 表盘目录为空或参数无效 | 把 `watchuiCoustom` 的“自定义表盘数量”误当作 `dialShape` | `watchuiCoustom` 永远不得参与 `dialShape` 推导；商城 profile 必须同时具备厂商、设备标识、名称、设备号、固件、屏幕宽高、形状、协议、最大长度、槽位和兼容指纹，缺一项就关闭商城，不得套用 W9S 默认值 |
| iOS 表盘目录为空、标题或下载参数沿用 Android | iOS 曾复用 Android 厂商目录和直接 HTTP 下载，未经过 Veepoo iOS 原生会话 | iOS 目录与下载统一调用 `VPMarketDialManager`；返回 ID、真实路径和长度绑定当前连接代次与设备 profile，Flutter 层不得回退到 Android 目录 |
| 换表后仍展示旧目录，或传输完成但手表未真正切换 | profile/目录缓存没有绑定设备代次；把传输进度完成误判为安装成功 | 换表、断连和重连都清空旧 profile、目录与缩略图缓存；传输前重新核对当前设备、兼容指纹、尺寸、协议和长度；传输后必须回读当前表盘路径或 ID，回读一致才算成功 |
| iOS 电量显示成错误百分比，或旧手表回调覆盖新手表 | 百分比和四格电量共用一个数值解释；异步回调没有连接代次保护 | 电量必须保留数值、刻度/百分比类型、低电、充电和更新时间；`3/4 格` 不得显示成 `3%` 或推算成 `75%`；每次连接生成代次标识，迟到回调只允许更新发起读取时的同一设备，断连清空，读取超时不得误判断连 |
| 电量、同步、测量或表盘传输互相抢占导致超时 | 多个耗时 SDK 命令可同时进入厂商单命令通道 | 四类操作使用同一原生命令互斥；分别设置一次性超时和连接代次校验，完成、失败、断连都必须释放锁，迟到回调不得释放下一任务的锁 |
| 在线升级误导用户或把 App 锁死 | 平台更新渠道混用；清单请求失败仍沿用旧强更判断 | iOS 生产版只允许跳转具体 `apps.apple.com` 产品页，不直装 IPA；Android APK 必须先校验 SHA-256，再交给系统安装器校验同包名和同签名；只有成功取得并完整校验的新清单，且当前构建低于 `minimum_supported_build` 时才能强更，404、超时、格式错误或签名/哈希异常都不得触发强更 |
| 手动检查绕过强更或重定向绕过域名白名单 | 启动检查与页面检查各自持有状态；校验只看初始 URL | 启动和手动检查统一走应用根级 Gate；必要更新状态即使持久化失败也不能解除；清单和 APK 每次重定向及最终地址都必须为同源 HTTPS |
| Android Release 带入高风险权限或 ABI 门禁被一刀切关闭 | 插件 Manifest 合并未审计；JCore 锁定版本只提供单架构可选库 | Release 显式移除后台定位、读取电话状态和查询全部应用权限；ABI 只允许锁定 JPush/JCore 组合下 `libjutils.so` 精确例外，版本或文件集合变化立即失败 |
| 发布时清单与 APK 不一致，或失败后线上停在半成品 | 并发发布缺少互斥和条件写入，覆盖前也没有可验证回滚点 | 发布必须使用互斥锁和基于线上清单哈希的 CAS；先发布不可变产物，再原子替换清单；公开地址验证失败时立即恢复旧清单并再次验证，锁冲突或 CAS 不一致直接停线，过期锁只能按明确的恢复流程处理 |
| 真机表盘测试改变了用户原表盘 | 临时安装前没有记录原表盘，结束时也没有回读确认恢复 | 临时表盘测试必须记录设备、时间、原表盘路径/ID、目标表盘和操作结果；验收结束恢复原表盘并回读确认，恢复失败立即登记为阻断，不得声称测试完成 |
| 远程关爱指标详情混入整行字段 | 通用详情卡遍历远端整行，未按当前指标投影；无效时间又被直接格式化 | 详情必须使用指标白名单和中文单位；HRV 只显示 HRV，血压拆收缩/舒张，标量指标互不混入，复合指标只保留相关子项；负数/无效时间显示记录序号；当日摘要不得扩展成伪周/月趋势 |
| 关于页遇到异常短文本或脏数据显示异常 | 页面缺少异常长度和非预期响应的防御性回退 | 远端文案必须先校验结构和最小可用内容；异常时显示本地安全回退，不截取、不拼接未经确认的数据；客户端修复后仍需异常样本复测 |
| W8 相机被系统策略禁用时保持黑屏 | 系统明确拒绝相机能力，但页面没有把不可用原因转成用户提示 | 系统策略拒绝必须结束加载并显示明确提示；不得保持黑屏或伪称设备相机已打开；客户端修复后已完成禁用与恢复两段真机复测 |
| JPush 插件日志回显客户端标识 | 上游 Android 插件无条件记录完整 `setup` 参数，SDK Debug 模式还会增加底层日志 | 锁定本地 `jpush_flutter 3.5.1` 源码并移除参数日志；厂商详细日志在所有构建模式关闭，只保留脱敏连接/重试状态；最终真机日志确认 AppKey 精确值和 Registration ID 形态均未出现 |
| 心电命令 ACK 被误写成波形通过 | ACK 只表示设备接受启动/停止命令，未佩戴或接触不良不会产生有效波形 | 心电验收必须分为命令 ACK、佩戴/接触、实时样本、波形质量、保存和历史同步；缺任一环节都不能写完整通过 |

## 追加停线条件：本轮上线门禁

以下任一情况发生时，同样不得提交为“上线完成”：

- 红点仍为固定状态，或陈旧远端未读能覆盖新本地事件。
- 推送包含白名单外字段、健康隐私或任意路由。
- 生产发布未经过受保护 Environment，或缺少推送、签名、更新必需配置却仍可继续。
- 表盘 profile 不完整、换表未清缓存，或传输后未回读设备状态。
- 电量把百分比与四格混算，或旧连接回调可覆盖当前设备。
- 更新清单请求或校验失败时仍进入强制更新。
- 发布没有 CAS、互斥锁或可验证回滚，或真机临时表盘未恢复并确认。
- 任一健康或消息查询没有账号 owner，或换号后旧代次请求仍可落库。
- v5 遗留数据可被非升级时已持久化账号认领、认领不是单一事务，或首次未登录迁移后未写 secure-vault marker。
- iOS 表盘目录绕过原生 Veepoo 会话，或电量、同步、测量、传输可并发占用 SDK 命令通道。
- 更新页可绕过根 Gate，或清单、APK 的最终重定向地址未重新执行同源 HTTPS 校验。
- 只取得心电命令 ACK、JPush TCP 在线或客户端修复，却把有效波形、业务通知或真机场景写成通过。
- 交接资料包含 AppKey、RID、Token、AuthKey 或其他可复用推送凭据。
