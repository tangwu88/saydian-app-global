## 可复现问题与影响

诊断文件：[`tool/diagnostics/u19_measurement_lifecycle_test.dart`](../tool/diagnostics/u19_measurement_lifecycle_test.dart)。它使用合成内存数据和公开控制器 API，不访问手机、手表、生产存储或网络；显式运行，未放入默认 `test/` 目录。断言表达正确目标行为，当前失败是未修复问题，不是预期成功。

| 编号/等级 | 复现、预期与实际 | 相关代码 |
| --- | --- | --- |
| U19-AUDIT-01 / P1 | 对可测量但不可从 App 停止的设备，启动并收到有效结果。预期清理活动测量；实际记录已出现但 `activeMeasurementMetric` 仍占用。 | `lib/services/app_controller.dart` 的 `_saveWearableRecord` 把本地清理附加在支持停止的条件下。随后仍有无条件停止调用，诊断在前一断言失败，后续停止次数/再次开始断言尚未动态执行。 |
| U19-AUDIT-02 / P1 | 测量中分别触发原生断线、点击断开。预期旧会话结束并释放占位；两条路径实际均残留活动测量。 | `disconnectDevice` 与 `disconnected` 事件分支。两个独立诊断均失败；账号切换已有另一套清理，不混为同一结论。 |
| U19-AUDIT-03 / P1 | 已发起的同步返回前收到 `healthDataReady`。预期完成后补读一次，避免遗漏快照之后的新结果；实际丢弃通知，没有补读。 | `healthDataReady` 分支在 `isDeviceSyncing` 时直接跳过。诊断预期总读取 3 次，实际 2 次。 |
| U19-AUDIT-04 / P1 | U19 正常入口要求血压/心率/血氧测量与结果同步。实际能力为空且同步仅有当天步数/睡眠。 | `lib/services/urion_wearable_bridge.dart` 的 `getCapabilities`、`syncHealthData` 和主动通知处理。启动指令存在不代表完整流程已接通。 |
