## P1：传递依赖漂移导致 ABI 门禁失败

- 复现：在未修改源码时执行双 ARM `flutter build apk --release`，随后运行 `release_gate.py apk-abis`。首次未提供当前 Gradle 依赖报告被门禁拒绝；补齐报告后，发现 `cn.jiguang.sdk:jpush:6.2.0` 的动态 JCore 依赖解析到 `5.5.7`，而门禁只允许已审计的 `5.5.2`。
- 预期：每次打包都解析到已核准的 `jpush_flutter 3.5.1 + JPush 6.2.0 + JCore 5.5.2`；`libjutils.so` 仅 arm64 的精确例外可复核。实际：漂移到 `5.5.7`，双 ARM 包虽可生成但门禁失败。影响：P1，未修正的 APK 不得作为已通过 QA 的交付包。首次产物 SHA-256 `C4C20A3DBBB180F2E32DB60FB4FEA7049455F14CA33EAC7B49688F5744C0DBC7`，**未上传**。
- 修复：仅在 `android/build.gradle.kts` 现有 `resolutionStrategy` 中锁定 `cn.jiguang.sdk:jcore:5.5.2`，不修改 ABI 门禁或推送业务逻辑；Android CI 增加当前依赖报告与 APK 的 ABI 门禁，防止未来静默漂移。重生成的 `releaseRuntimeClasspath` 确认为 JPush `6.2.0`、JCore `5.5.2`。极光[官方版本说明](https://docs.jiguang.cn/jpush/jpush_changelog/updates_Android)建议 JPush 6.2.0 配合 JCore 5.5.0 及以上使用；该要求与已审计的 5.5.2 相容。
